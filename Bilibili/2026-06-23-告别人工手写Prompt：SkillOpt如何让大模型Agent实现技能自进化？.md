## 概述

**论文**：SkillOpt: Executive Strategy for Self-Evolving Agent Skills  
**论文地址**：https://arxiv.org/abs/2605.23904  
**项目地址**：https://github.com/microsoft/SkillOpt

> [!tip] 核心突破
> SkillOpt 是目前已知首个面向智能体技能的、**系统且可控的"文本空间优化器"**。它将技能视为参数冻结智能体的"外部状态"，用类似优化神经网络权重的方式去训练它，且**实际部署时不增加任何额外模型调用成本**。

---

## 1. 现有方法的三条"死胡同"

| 方法 | 比喻 | 问题 |
|------|------|------|
| **手工编写** | 给极其死板的说明书 | 极其耗时，人类脑容量穷尽不了边界场景，遇到突发情况直接崩溃 |
| **一次性生成** | 扔一本书就不管了 | 缺乏后续反馈，方案不管好坏就定死了，环境一变无法纠错 |
| **松散自反思** | 没有老师指导自己瞎琢磨 | 自然语言自由度太高，没有约束的自我反思极易偏离目标，走火入魔 |

> [!quote] 核心痛点
> 不是没试过让 AI 自学，而是它缺乏一个**靠谱的反馈老师**。

## 2. SkillOpt 的核心思路：文本空间优化器

### 2.1 范式转变

将传统深度学习优化器的理念应用到自然语言维度：

| 维度 | 传统深度学习 | SkillOpt |
|------|-------------|----------|
| **优化对象** | 深度网络里的数字权重 | 纯文档的智能体技能 |
| **评估信号** | 损失函数 | 带有评分的执行展开（实际跑分） |
| **更新步长** | 梯度下降，数字变大变小 | 具体的文本增删改操作 |

> [!abstract] 核心类比
> 去掉文档里一句容易引起歧义的指令，或插入一句特定的代码格式要求——**这就等同于调整了文本权重**。

### 2.2 双引擎架构

```
┌─────────────────────────────────────────────────────┐
│                    SkillOpt 系统                      │
│                                                     │
│  ┌──────────────────┐    ┌─────────────────────┐    │
│  │  左侧：执行智能体   │    │  右侧：优化器模型      │    │
│  │  （冻结参数）      │    │  （独立于执行过程）    │    │
│  │                  │    │                     │    │
│  │  赛车手：          │    │  维修站工程师团队：     │    │
│  │  只管在赛道上开车   │    │  分析遥测数据         │    │
│  │  读取技能文档干活   │    │  调整赛车零部件       │    │
│  │                  │    │  改写技能文档         │    │
│  └──────────────────┘    └─────────────────────┘    │
│                                                     │
│  部署时：左侧独立运行，零额外开销                      │
└─────────────────────────────────────────────────────┘
```

> [!tip] 关键设计
> 赛车手（执行智能体）自己完全不需要一边开车一边修车。繁重的优化计算全被移到系统外部，**推理部署时没有任何额外的算力负担**。

## 3. 内部优化循环：四个严密步骤

```
Step 1: 评分轨迹生成          Step 2: 生成编辑
赛车跑一圈，记录执行过程       工程师分析录像，提出受控文本修改
    ↓                          ↓
Step 4: 接受/拒绝门控          Step 3: 流出验证集
只有严格提升才接受            在全新测试数据上评估修改后的技能
```

| 步骤 | 说明 | 关键点 |
|------|------|--------|
| **1. 评分轨迹生成** | 执行任务，记录过程，得出初始分数 | "赛车跑一圈" |
| **2. 生成编辑** | 优化器分析轨迹，提出受控文本修改（删除/增加/替换） | "工程师看录像找问题" |
| **3. 流出验证** | 将修改后的技能放到**未见过的测试数据**上评估 | 绝不凭一次执行拍板 |
| **4. 接受/拒绝门控** | 得分**严格提升**才接受，否则无情拒绝 | 保证优化绝不倒退 |

> [!important] 冷酷的门控
> 如果一个技能在旧问题上表现极好，但在新问题上只是稍微搞砸了一点点——**也会被直接毙掉**。只要得分没有严格提升，修改建议就废了。这是优化的生命线。

## 4. 三重稳定器：确保训练不发散

| 稳定器 | 比喻 | 机制 |
|--------|------|------|
| **文本学习率预算** | 每天只能改十行代码的配额 | 严格限制每次更新的文本修改幅度（如 0.005-0.01），只能修饰极小一部分文本，防止灾难性遗忘 |
| **被拒编辑缓冲区** | 错题本，绝不在同一个坑跌倒两次 | 被拒绝的编辑存入缓冲区（最多 128 次），下次生成建议时当上下文喂给优化器，提供负面反馈 |
| **Epoch 级慢速更新** | 宏观周期把控大局 | 每 1-10 个 epoch 在更大时间尺度上评估全局优化趋势是否收敛 |

> [!note] 防发散总结
> 配额制限制冲动 + 错题本提供负反馈 + 宏观周期把控大局 = **滴水不漏的稳定训练**。

## 5. 实验结果：52 比 0 全矩阵领先

### 5.1 评估规模

| 维度 | 数量 |
|------|------|
| 基准测试 | 6 个 |
| 目标模型 | 7 个 |
| 执行环境 | 3 种（Direct Chat、Codex、Claude Code） |
| **评估组合** | **52 个** |

> [!success] 52 场全胜
> SkillOpt 在全部 52 个评估组合中排名**全部第一或并列第一**，达成毫无争议的绝对统治力。

### 5.2 GPT-5.5 上的性能提升

| 执行环境 | 准确率提升 |
|----------|-----------|
| 直接对话模式 | **+23.5** |
| Codex 智能体循环 | **+24.8** |
| Claude Code | **+19.1** |

### 5.3 为什么对手败北？

TextGrad、EvoSkill 等方案缺乏：
- 严格的验证集门控
- 三重稳定器
- 缺乏纪律性的反思，长线作战必败

## 6. 跨界迁移能力

优化出来的"技能产物"可以**零开销、无缝迁移**到不同场景：

| 迁移类型 | 说明 |
|----------|------|
| **跨模型规模** | 小模型优化出的技能直接拿给大模型用 |
| **跨执行环境** | Codex 优化好的文本直接拿到 Claude Code 去跑 |
| **跨任务** | 无需继续优化就能直接迁移到相邻的数学任务 |

> [!abstract] 类比
> 在模拟器里学会了开飞机的技能，不仅能直接去开波音，还能无缝切换去开空客——**完全不需要重新考驾照、交学费**。

---

## 7. 部署经济学：零推理成本

SkillOpt 将生命周期分为两个阶段：

| 阶段 | 占总生命周期 | 算力投入 | 说明 |
|------|-------------|----------|------|
| **Phase 1：技能训练期** | ~40% | 集中使用算力 | 生成、验证、试错——会花钱 |
| **Phase 2：部署运行期** | ~60% | **零** | 智能体直接读取优化好的文本技能执行，不再依赖外部优化器，无内部纠错循环 |

> [!tip] 最致命的杀招
> 前期花一笔研发费把"武功秘籍"写出来之后，不管谁用、用多久，**推理成本都是绝对的零**。获得了媲美甚至超越微调的自进化能力，却不增加任何线上运行的推理开销。
