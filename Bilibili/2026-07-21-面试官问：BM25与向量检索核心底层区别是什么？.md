## 概述

大模型搜索召回中 BM25 与向量检索的工程实践与融合策略。

> [!danger] 肤浅回答
> 如果回答"一个是关键词匹配，一个是语义匹配"——这是教科书式的肤浅回答，根本没有触及工业级检索的工程本质。
>
> **这道题考的压根不是背概念，而是你在实际业务里对精度、算力和泛化性做系统级权衡的那种体感。**

---

## 一、BM25：离散词空间的概率检索

### 1.1 本质

BM25 不是死板的"数词机器"，而是**经典概率检索模型的巅峰**。

```
分词 → 算词频（TF） → 算逆文档频率（IDF） → 加权评分
```

### 1.2 两个核心工程参数

| 参数 | 作用 | 说明 |
|------|------|------|
| **K1** | 控制词频饱和度 | 词频增长到一定程度后收益递减 |
| **B** | 控制文档长度归一化 | 长文档不会被天然劣势 |

### 1.3 优势与致命伤

| 维度       | 说明                        |
| -------- | ------------------------- |
| **优势**   | 贼快！倒排索引一拉，CPU 上跑得飞起       |
| **擅长场景** | 搜精准词、货号、专有名词——严格字面匹配，特别靠谱 |
| **致命伤**  | **完全没有离散空间的泛化能力**         |

**致命伤示例：**

```
用户搜索："笔记本散热支架"
手滑打成："笔记木散热支架"
→ BM25 当场就瞎了，直接零召回
→ 因为它只认那几个离散的词
```

## 二、向量检索：连续语义空间的高维匹配

### 2.1 本质

不走分词路线，而是用预训练模型把文本映射到 **768 维或 1024 维的高维浮点向量**里。

```
文本 → 预训练编码器 → 高维向量（768/1024 维）
    ↓
不关心字面对没对上，看余弦相似度
```

> [!tip] 语义雷达
> 向量检索特别擅长捕捉同义词和引申语义，等于给召回装了个"语义雷达"。

### 2.2 落地时的两个大坑

| 坑 | 说明 | 影响 |
|---|------|------|
| **算力大户** | 查询要实时过编码器，底层还要做 ANN（近似最近邻）搜索，如 HNSW 或 IVFPQ | 要在召回率和 QPS 间反复横跳，显存压力极大 |
| **意图漂移** | 用户精确搜索"iPhone 16 Pro Max"，向量检索可能因为语义相关推一堆评测文章 | 太活泛了，精准需求反而被模糊化 |

---

## 三、对比总结

| 维度 | BM25 | 向量检索 |
|------|------|---------|
| **空间** | 离散词空间 | 连续语义向量空间 |
| **匹配方式** | 严格字面匹配 | 余弦相似度 |
| **核心能力** | 精准词、货号、专有名词 | 同义词、引申语义 |
| **泛化能力** | 无 | 强 |
| **算力** | CPU 即可，倒排索引 | 需要 ANN 搜索，显存压力大 |
| **致命缺陷** | 拼写错误 = 零召回 | 意图漂移，精准搜索被模糊化 |

## 四、LLM 前置：Query 改造

单靠召回端发力是不够的。现代 RAG 的第一道分水岭在于**检索前的大模型**。

### 4.1 针对 BM25 的硬伤

> **纠错 + 同义词扩展**

```
"笔记木" → LLM 纠错 → "笔记本"
→ BM25 精确召回瞬间拉满
```

### 4.2 针对向量检索的漂移

> **上下文补全 + HyDE 技术**

```
用户查询 + LLM 上下文补全 → 意图被锁定
→ 向量检索的泛化才不会乱飘
```

> [!important] 核心原则
> **只有把 Query 盘顺了，才轮到混合检索架构亮出来。**

---

## 五、混合检索架构：工业级标准打法

线上稍微有点体量的系统**绝对不是二选一**，都是**双路甚至多路召回并行**，然后融合。

### 5.1 双路召回

```
                    ┌─ BM25 路：死死卡住精准关键词 ─┐
Query ── LLM 改写 ─┤                               ├── 结果融合
                    └─ 向量检索路：猛拉长尾召回上限 ─┘
```

| 路 | 作用 | 说明 |
|---|------|------|
| **BM25 路** | 守住精准关键词的底线 | 防止意图漂移 |
| **向量检索路** | 拉长尾查询的召回上限 | 把字面不匹配但意思相关的捞回来 |

### 5.2 RRF 融合（倒数排名融合）

> [!warning] 别简单加和
> BM25 的得分和余弦相似度根本不在一个量纲上。

**工程上首选带权重的 RRF（Reciprocal Rank Fusion）：**

```
RRF 得分 = Σ(1 / (k + rank))
```

- 只关心每条结果在两路中的**排序位置**
- 取倒数求和
- **完美绕开分数归一化这个大坑**

### 5.3 完整链路

```
LLM 前置（意图识别 + Query 改写）
        ↓
    多路召回并行（BM25 + 向量检索）
        ↓
    RRF 融合排序
        ↓
    Cross-Encoder 交叉编码器精排
        ↓
    最终结果
```

> [!success] 面试官想听到的
> 从 LLM 前置的意图识别、Query 改写，一路聊到多路召回融合和精排。他想知道你不仅懂单点技术的优劣，还清楚在**系统架构上怎么把算力、精度、泛化性平衡好**。

## 关键 Takeaways

| # | 要点 |
|---|------|
| **1** | BM25 是离散词空间的概率检索，核心参数 K1（词频饱和度）和 B（文档长度归一化） |
| **2** | 向量检索将文本映射到高维向量空间，擅长语义匹配但算力消耗大且容易意图漂移 |
| **3** | 两者根本区别在于**离散词空间 vs 连续语义向量空间**的数学鸿沟 |
| **4** | 工业系统不是二选一，而是**双路召回 + RRF 融合 + Cross-Encoder 精排** |
| **5** | 现代 RAG 的第一道分水岭是**检索前的 LLM Query 改写**，不是召回端本身 |
