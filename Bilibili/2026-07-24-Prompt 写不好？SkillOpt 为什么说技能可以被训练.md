## 概述

SkillOpt 把 Agent 的技能文档当作**可训练的外部状态**：冻结目标模型权重，用优化器模型在文本空间内持续编辑技能文档，通过前向执行→反向反思→步长控制→验证门控的闭环，自动产出 `best_skill.md`。它不是"写更好的 prompt"，而是把技能管理变成**工程化、版本化的软件发布过程**。

> [!abstract] 一句话总结
> SkillOpt = 冻结模型 + 外部技能文档优化：用**文本空间的训练循环**替代黑盒微调，靠编辑预算控制步长、验证门控防退化、rejected-edit buffer 避错，最终只部署一份纯文本 `best_skill.md`。

## 一、为什么需要 SkillOpt

### 传统提示词工程的三大痛点

| 路径 | 问题 |
|------|------|
| **人工撰写规则** | 难以穷尽真实多变的交互边界 |
| **LLM 单次生成** | 复杂场景下成功率极低 |
| **自动化脚本试错** | 缺乏输入约束，盲目修改 → 黑盒输出 |

### 核心缺陷

```
主观闭环：缺乏定量数据反馈 → 优化凭运气
    ↓
反馈失真：受模型随机性影响 → 拖入不可预测的错误循环
    ↓
语义漂移：多轮修改中不断堆砌旁支逻辑 → 核心指令被丢弃
    ↓
单一案例过拟合：为修复某错误硬编码 → 按下葫芦浮起瓢
```

> [!warning] 最大局限
> 传统模式将**简单的提示词工程**错误地等同于**严密的系统级工程**，忽视退化风险，缺乏标准化评估指标。

### SkillOpt 的解法：引入机器学习纪律

| 阶段 | 职责 |
|------|------|
| **训练集** | 产生候选技能编辑，自由探索 |
| **验证集** | 安全门控，只有超越当前版本才允许合入 |
| **测试集** | 完全物理隔离，最终客观评估泛化性能 |

> [!important] 核心启示
> 构建优秀的智能体，绝不能奢望靠玄学般的精妙提示词。架构师必须退一步，构建一套能够**自我沉淀和自我纠偏的机制**。

## 二、核心架构：参数冻结 + 外部状态优化

### 两个角色的分工

| 角色 | 职责 | 权重状态 |
|------|------|----------|
| **目标模型** | 执行具体任务，加载技能文档做零样本推理 | **完全冻结** |
| **优化器模型** | 分析执行轨迹，编辑技能文档 | 独立使用 |

### 对比传统微调

| 维度 | 传统微调 | SkillOpt |
|------|---------|----------|
| **优化对象** | 模型权重（连续向量空间） | 技能文档（离散文本空间） |
| **算力开销** | 极高 | **零显存微调开销** |
| **可解释性** | 黑盒 | 纯文本，100% 可读 |
| **灾难性遗忘** | 高风险 | 完美避免 |
| **部署形态** | 新权重文件 | 一份 `best_skill.md` |
| **泛化能力** | 容易过拟合 | 保持通用泛化 |

### 技能文档的四大要素

| 要素 | 作用 |
|------|------|
| **程序逻辑** | 控制算法流向与执行框架，是基础底座 |
| **工具调用策略** | 精准定位何时调度外部接口，自动提取参数 |
| **输出规范** | 强校验格式化输出，转化为下游可用的结构化数据 |
| **失败恢复机制** | 捕获错误→动态反思纠偏→自动重试 |

## 三、文本空间训练循环

SkillOpt 将传统深度学习的训练循环映射到了**离散的自然语言文本空间**：

```
传统深度学习                    SkillOpt 文本空间
    │                                │
    ├── 前向传播 → 计算损失           ├── 前向执行 → 收集轨迹+得分
    │                                │
    ├── 反向传播 → 计算梯度           ├── 反向反思 → 生成文字批判+修正方案
    │                                │
    ├── 学习率 → 控制步长            ├── 编辑预算 Lt → 控制修改条数
    │                                │
    └── 验证集 → 评估泛化            └── 验证门控 → 回归测试准入
```

### 四步闭环

| 步骤 | 操作 | 类比 |
|------|------|------|
| **1. 前向执行** | 目标模型加载当前技能文档执行任务，记录完整轨迹（消息流、工具调用参数、环境观察、最终答案、量化得分） | 前向传播 |
| **2. 反向反思** | 优化器模型分析成功与失败轨迹，归因缺陷，生成自然语言修正方案 | 反向传播 |
| **3. 步长控制** | 编辑预算 Lt 限制单次修改条数，防止过度修改破坏上下文 | 学习率 |
| **4. 验证门控** | 候选技能在独立验证集上回归测试，必须严格超越当前版本才合入 | 验证集评估 |

> [!tip] 前向执行的五维轨迹
> 系统无感抓取：**消息流** + **工具调用参数** + **环境观察** + **最终答案** + **量化得分** → 把黑盒交互解构成客观日志。

### 反向反思的双向分析

```
失败轨迹 → 归因分析 → 定位缺失规则与错误引导
    +
成功轨迹 → 行为标定 → 锚定已生效的高质量行为模式
    ↓
合并 → 去重 → 优先级排序 → 候选编辑池
```

> [!important] 为什么双向分析
> 只看失败容易反应过度破坏原有逻辑；只看成功会遗漏隐藏盲区。双向分析是**防范灾难性遗忘的底层保险**。

## 四、编辑预算（文本空间的学习率）

### 核心机制

```
候选编辑池
    │
    ▼
┌─────────────────┐
│   编辑预算 Lt    │  ← 全局超参数，控制单步最大修改条数
└────────┬────────┘
         │ 漏斗过滤
         ▼
   预算内的最优修改
         │
         ▼
   应用到技能文档
```

### 与深度学习学习率的映射

| 深度学习   | SkillOpt 文本空间   |
| ------ | --------------- |
| 梯度更新方向 | 最优语言反馈修改项       |
| 学习率 η  | 编辑预算 Lt（最大修改条数） |
| 连续参数更新 | 离散文档编辑          |

### 预算设定的权衡

| 预算过低        | 预算过高          |
| ----------- | ------------- |
| 安全稳定        | 演进迅速          |
| 迭代周期漫长、耗费算力 | 局部语义失控、系统能力崩溃 |

> [!note] 黄金法则
> 在**平滑过渡**与**高效爬升**之间寻求动态平衡。编辑预算 = 文本空间的梯度步长。

## 五、验证门控与 Rejected-Edit Buffer

### 门控准入流程

```
候选技能
    │
    ▼
┌──────────────────────┐
│   独立验证集回归测试   │
└──────────┬───────────┘
           │
    ┌──────┴──────┐
    │             │
  通过 ✓        未通过 ✗
    │             │
    ▼             ▼
合入主干      丢弃 + 存入 rejected-edit buffer
(best_skill)   （负面坐标系，避免重蹈覆辙）
```

### 双轨资产归档

| 结果          | 归档位置                       | 作用              |
| ----------- | -------------------------- | --------------- |
| **超越历史最优**  | `best_skill.md`（持久化更新）     | 追逐质量天花板         |
| **落后基准被拒绝** | 负样本库（rejected-edit buffer） | 标记失败安全边界，约束后续生成 |

> [!quote] 正负反馈双向驱动
> 正向最优探索追逐天花板，负向边界约束标记安全线——共同实现高效自适应调优。

## 六、数学形式化

### 技能执行公式

当模型权重 M 锁定时，调优空间完全转移到技能变量 S 上：

```
给定相同模型 M 和题目 X：
  S₁ → 推理轨迹 T₁, 得分 R₁
  S₂ → 推理轨迹 T₂, 得分 R₂

→ 仅改变技能文档 S，就能引发截然不同的思考过程与结果
→ S 是可独立优化的变量
```

### 技能筛选目标

```
S* = argmax_S [ avg(R(S, V)) ]

其中 V 是独立验证集，R 是量化得分。
只有跨过这道验证门槛的技能，才真正具备部署价值。
```

> [!danger] 防范"虚假聪明"
> 绝不能只看训练表现。大模型很容易为迎合数据而死记硬背特定解题捷径。真正的试金石是：**在从未见过的验证题目上取得实打实的量化性能提升**。

## 八、适用场景与局限性

### 适用场景

| 领域              | 原因               |
| --------------- | ---------------- |
| **定理证明 / 数理逻辑** | 严密演绎步骤，确定性反馈     |
| **代码编写**        | 可直接用单元测试或编译器报错验证 |
| **策略博弈（棋盘等）**   | 胜负事实客观明确         |
| **高频复用的核心模块**   | 训练成本可被海量应用摊薄     |

### 不适用场景

| 领域              | 原因           |
| --------------- | ------------ |
| **文案创作 / 开放内容** | 缺乏绝对对错标尺     |
| **主观审美评价**      | 无法提供高保真评价刻度  |
| **多冲突目标博弈**     | 难以折算为单一可靠分数  |
| **一次性临时任务**     | 训练成本远超任务边际收益 |

### 三层架构定位

```
┌─────────────────────────────────────┐
│  外层：RAG（知识检索与调度）         │  ← 处理海量外部知识/多智能体交互
├─────────────────────────────────────┤
│  中层：SkillOpt（提示词执行逻辑优化） │  ← 免算力、分钟级反馈、最后一公里助推
├─────────────────────────────────────┤
│  底层：Fine-tuning（模型参数微调）    │  ← 注入核心常识、基础认知能力跃迁
└─────────────────────────────────────┘
```

> [!warning] 不可替代的边界
> 1. 无法替代系统级的知识检索与调度机制（RAG 层）
> 2. 无法弥补基座模型的严重智力缺陷（需要 fine-tuning）

### 训练成本考量

```
决策黄金法则：

技能复用次数 × 长尾估值 >> 单次实际执行 + 优化器迭代总成本

追求高边际收益，规避一次性散碎任务。
```

## 九、扩展思考

### 与强化学习结合

在 RL 探索初期插入**门控拦截机制**：精准剪枝无效与非法动作，压缩无差别探索空间，显著提升奖励优化的收敛稳定性。

### 主观任务的替代评价器

对于创意写作等缺乏明确反馈的任务，可构建**自动评价器**：多维度打分 + 缺陷定位 + 针对性修改意见，从语义一致性和逻辑合理性逼近金标准。
