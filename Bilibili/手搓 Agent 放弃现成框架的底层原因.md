# 手搓 Agent 不是炫技！讲解放弃现成框架的底层原因，以及自研 Agent 适合哪些项目场景

## 一句话总结

> [!tip] 核心结论
> 手搓 Agent 不是跟框架较劲，而是拿回三样东西：==对 ReAct 循环的完整主权、上下文工程与成本的极致压缩、流式体验与调度秩序==。
>
> 框架帮你验证需求，手写把控制权拿回来。关键路径一旦上生产，就得收回自己手里。

## 面试题背景

> [!question] 面试官的问题
> 你做 Agent 为什么坚持手写，不用 LangChain 这种成熟框架？
>
> 你脱口而出：因为框架太重了，我想自己掌控细节。
>
> 三连追问来了：
> 1. 重在哪里？包体积重还是抽象重？
> 2. 框架替你省下的时间，你自己补得回来吗？
> 3. 你手写这一版，凭什么比一个几万人用过的框架更稳、更好维护？

> [!warning] 很多人当场卡住
> 三问砸下来，很多人当场卡住。

## 框架真正的痛点：看不见、追不上

### 看不见：抽象层遮住了底层

> [!note] 早年 LangChain 的调用链
> 调一次最简单的文本生成请求，要穿过：
>
> `Chain` → `LLM` → `Chain Base` → `LLM Base` → `OpenAI` → 最后才到模型
>
> 你以为你写的是提示词，其实模型收到的是被框架重新拼装过的东西。

> [!quote] Anthropic 官方工程博客《Building Effective Agents》
> 框架为了通用，加了额外抽象层，把底层提示词和返回结果都遮住，调试变难。所以他们建议开发者先从原生 API 写起，很多模式几行代码就能实现。真要用框架，前提是你搞懂它底下在干什么。
>
> 因为线上最常见的坑就是：==你以为它这么干，它其实那么干。==

### 追不上：版本漂移

> [!warning] LangChain 的路线图变迁
> - 早年的 `Chain` 后来被 LCEL 管道取代。
> - 到了 LangChain 1.0，`create_react_agent`、`AgentExecutor` 这些老接口又迁到 `LangChain Classic`。
> - 官方推荐改成了 `create_agent` + 中间件。
>
> 业务一行没变，框架的路线图变了，代码就得重写。这不是技术不行，是节奏被别人牵着走。

> [!example] 真实案例：Octomind
> 做自动化测试的团队 Octomind 在生产环境用 LangChain 跑了一年多，最后整个移除。
>
> 原因很具体：他们要根据业务逻辑和模型输出，动态调整 Agent 能调哪些工具。但框架没有从外部观察 Agent 内部状态的机制，最后只能缩减需求去迁就框架。
>
> 他们的原话是：==删掉框架之后，我们不用再把需求翻译成它能接受的样子，直接写代码就行。==

## 手写 Agent 的价值：拿回三样东西

> [!important] 记住一句
> 手写不是跟框架较劲，是拿回三样东西。

### 第一样：对 ReAct 循环的完整主权

> [!success] 框架的黑盒 vs 手写的白盒
> 框架把「思考 → 调工具 → 拿结果」分成黑盒。Agent 跑偏了、参数填错了、开始原地打转，你插不进去。
>
> 自己写就不一样：
> - 每一步在想什么、调了什么工具、返回值合不合理，都能实时插装、拦截、修正。
> - 工具执行前可以加校验和权限。
> - 判断跑飞了能立刻中断。
> - 关键节点还能让人介入。
>
> ==可观测只是基础，可干预才是底气。==

### 第二样：上下文工程和成本的极致压缩

> [!warning] 框架的系统提示问题
> 框架为了兼容各种场景，系统提示里往往塞着通用模板。你动其中一行，前缀就变了，服务端的前缀缓存直接失效，==token 白烧==。

> [!tip] 自己写才能做前缀治理
> - 系统提示和工具定义固定在最前面。
> - 中间只追加工具。
> - 返回太大就截断或者落盘。
> - 历史超阈值就折叠、摘要。
>
> 像 [[Claude Code]] 这类成熟产品，自带上下文压缩，走的就是这个思路。
>
> 省的不是小钱，是每次调用都在省。

### 第三样：流式体验和调度秩序

> [!important] 决定用户体感的从来不是模型本身
> 是外面那层 [[Harness]]。

- 模型还在推理，思考过程和工具状态已经流式推到前端。
- 读文件、查资料这种只读操作，可以放心并发。
- 改代码、跑命令这种写操作，必须严格排队串行。
- 一旦超时或者异常，一个中断信号就得马上停住。

> [!quote] 这种调度框架很难替你做到。

## 框架就一文不值吗？

> [!note] 别走极端
> 框架的价值在 **验证阶段**：
> - 快速搭 demo。
> - 跑通链路给团队看效果。
> - 确实省时间。
>
> 但一旦要上生产：
> - 要控成本。
> - 要控权限。
> - 要控稳定性。
>
> 关键路径就得收回自己手里。

| **OpenAI Agents SDK** | 学最干净的工程范式 | 将近 3 万行，Agent Runner、Guardrail、Handoff 拆得很干净，白盒化设计的样板 |
| **Aider** | 学上下文工程 | 接近 5 万星，用 tree-sitter 扫一遍仓库，生成符号地图，几千个 token 让模型看懂整个项目改写文件，还能在 hunk 和 diff 之间切换 |
| **Goose** | 看 MCP 怎么落地、系统级并发长什么样 | 50000 多星，Rust 写的本地通用 Agent，由 Block 孵化，现在捐给了 Linux 基金会旗下的 AAIF |
| **PydanticAI** | 想写类型安全的生产级 Agent | 快 2 万星，Pydantic 团队出品，把 FastAPI 那套类型安全体验搬进 Agent，依赖注入、类型化工具、结构化输出全都有 |
