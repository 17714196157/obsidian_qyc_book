# 没有标准答案的任务怎么做 RL？给裁判一份参考回答，比 SFT 蒸馏高 20 分

> [!info] 来源
> - 视频：[Bilibili BV1tSea6ZEQm](https://www.bilibili.com/video/BV1tSea6ZEQm/)
> - UP 主：古希腊掌管代码的神
> - 上传日期：2026-09-26
> - 参考论文：arXiv 2602.16802
> - 相关概念：[[RLVR]]、[[LLM-as-Judge]]、[[奖励模型]]、[[自我改进循环]]、[[软验证器]]

> [!summary] 一句话
> 给 LLM 裁判一份参考回答，让裁判从“主观打分”变成“对照校验”，即可在写作、对话、总结等 ==没有标准答案== 的任务上做 RL / 自我改进。


## 1. 问题：非可验证任务卡在裁判不可靠

### 可验证奖励 RLVR
- 数学：比答案。
- 代码：跑测试。
- 优点：reward 干净，RLVR 的红利主要来自这里。

### 非可验证任务
- 写作、对话、总结等开放任务没有唯一答案。
- 只能让 [[LLM-as-Judge]] 当裁判打分。

> [!warning] LLM 裁判的典型问题
> - 凭空打分，标准漂移。
> - 偏爱更长的回答。
> - 偏爱排在前面的回答。
> - 偏爱自己风格的回答。
> - 同一回答两次打分可能不一致。
>
> 用这种 reward 做 RL，模型学到的可能是 ==讨好裁判==，而不是真正提升任务质量。

## 2. 解法：给裁判一份参考回答

在裁判 prompt 里带上一份参考回答，让裁判对照判断：

- 这条回答比参考 ==好在哪==？
- 这条回答比参考 ==差在哪==？
- 然后再打分。

> [!tip] 关键理解
> 参考不是让模型抄，而是 ==校准裁判的尺子==。裁判从主观打分器变成 [[软验证器]]。

### 参考来源怎么选

| 裁判能力 | 推荐参考来源 | 原因 |
| --- | --- | --- |
| 能力弱的裁判 | 前沿模型生成 | 自己判不准，参考给它一个锚 |
| 能力强的裁判 | 人写高质量参考 | 前沿模型参考它自己也能写，人写参考带来额外信息 |

## 3. 自我改进循环

1. 策略模型对每条 prompt 采样多条回答。
2. 参考引导的裁判给每条回答打分。
3. 用分数做偏好训练或 RL 训练。
4. 训练后的模型重新采样，迭代若干轮。

> [!success] 优点
> - 不需要人工标注偏好。
> - 不需要专门训练一个奖励模型。
> - 只需要每条 prompt 一份参考。

## 4. 实验结果

| 模型 | AlpacaEval | Arena-Hard |
| --- | ---: | ---: |
| Llama-3-8B | 73.1% | 58.7% |
| Qwen2.5-7B | 70.0% | 74.1% |

对比：
- 比 SFT 蒸馏高 ==20.2 / 17.1 分==。
- 比无参考的自我改进高 ==5.3 / 3.6 分==。
- 与专门微调的 [[奖励模型]] 相当。

> [!quote] 一句话
> 一份参考，顶一个奖励模型。

## 5. 实操四条

> [!todo] 实操清单
> - [ ] 每条 prompt 准备一份参考。
> - [ ] 弱裁判配前沿模型参考；强裁判配人写参考。
> - [ ] 裁判 prompt 写清楚：==对照参考评估==，不是匹配参考。
> - [ ] 配合长度和位置去偏，比如交换顺序打两次取平均。
> - [ ] 迭代 2-3 轮，每轮重新采样。

> [!danger] 边界
> 参考质量决定上限。参考错了，裁判会跟着错。

## 6. 总结
1. 非可验证任务的 RL 卡在裁判不可靠：凭空打分、偏长、偏位置。
2. 给裁判一份参考回答，把它当软验证器；弱裁判配前沿参考，强裁判配人写参考；参考是校准，不是让模型抄。
3. 自改进循环下，Llama-3-8B AlpacaEval 73.1%、Arena-Hard 58.7%；比 SFT 蒸馏高 20 分，比无参考高 5 分，追平专训奖励模型。
