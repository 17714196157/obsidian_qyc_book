# 用JEV做RAG重排器：成本约为LLM方案的十分之一

<iframe src="https://player.bilibili.com/player.html?aid=117306982140107&bvid=BV1U1he6tE6K&cid=42071362124&page=1&autoplay=0" scrolling="no" border="0" frameborder="no" framespacing="0" allow="fullscreen; picture-in-picture" allowfullscreen="true" style="height:100%;width:100%; aspect-ratio: 16 / 9;"> </iframe>

> [!abstract] 一句话总结
> 把 [[TypeSafe AI]] 的 [[JEV]] 接进 [[RAG]] 流程，用**可写成策略的判定标准**替代传统 [[cross-encoder]] 重排器，让检索结果按==业务逻辑==而非单纯语义距离排序。BM25 基线 Top-1 准确率 ==21%==，加入 JEV 重排后提升到 ==54%==。

## 核心观点

- [[JEV]] 适合处理 RAG 流程中的**决策点**：重排器、过滤器、引用判断等。
- [[cross-encoder]] 无法遵循指令，能力相对固定；一旦组织政策变化而业务逻辑不变，它就容易失效。
- [[LLM]] 重排器能按标准排序，但==成本高、速度慢==，难以实际采用。
- JEV 兼具**良好的可控性**与**极低的成本**，是即插即用的替代方案。

> [!tip] 成本对比
> JEV 的成本约为 LLM 重排方案的 **1/10**。文本块较小时，JEV 与 Gemini Flash-Lite 性能、成本接近；随着文本块变大，LLM 成本基本呈线性增长，而 JEV 的优势最明显。

## JEV 的三种基本能力

| 能力 | 说明 | 典型用途 |
|------|------|----------|
| 二元决策 | 创建工具调用分类器 | 判断文档是否符合标准 |
| 选项排序 | 定义标准，从多个选项中选出一个列表 | 重排、筛选 |
| 评分阶梯 | 为不同选项分配分数 | 分级排序 |

> [!note] 本视频重点
> 主要讲**重排（re-ranking）**，因为它是能同时展示 JEV 多种能力的典型例子。视频中使用的是 `narrow` 原语，输出**校准后的概率**（符合 / 不符合），可设定阈值做分类：高于阈值接受，低于阈值丢弃。

## 背景：为什么需要可编程重排

RAG 的典型痛点：

- 组织的**政策发生变化**，但实际的上下文或业务逻辑保持不变。
- 向量距离只能衡量**语义接近度**，无法根据业务逻辑判断正确性。
- 系统可能同时存在**多套相互竞争的政策**及其不同版本，需要在版本之间做判断。

例如查询「如何修复 API 返回的 401 未授权错误」时，官方 API 文档可能已更新，或者用户需要的是深入的架构说明，而不是快速复制的代码片段——这些都无法靠语义距离区分。

> [!example] 判定标准示例
> 指令要求判断某段文本是否**直接回答**问题，包含两项标准：
> 1. 给出问题所要求的具体答案（如「退款会在 14 天内退回原支付方式」）；
> 2. 仅包含与问题相同的词语或主题、却没有真正回答问题。
>
> 将四类查询（直接回答、主题相关但未回答、关键词匹配、完全无关）通过 `narrow` 标准处理后，JEV 会为==直接回答分配最高概率==，其余置信度很低。

## 并发性能

| 处理方式 | 吞吐 | 全部完成耗时 |
|----------|------|--------------|
| 串行处理 | 约 17 项判断/秒 | 约 40 秒 |
| 使用 64 并发池 | — | ==7.6 秒== |

> [!success] 结论
> JEV 很适合并发批量打分，利用官方提供的 64 并发池，速度明显快于逐项处理。

## 实验结果

以查询「如何修复 API 返回的 401 未授权错误」为例，对一批带元数据的文本块进行重排，对比多种方案：

| 方案 | 能否遵循指令 | 成本 | 速度 | Top-1 准确率 |
|------|--------------|------|------|--------------|
| [[BM25]] 基线 | — | — | — | ==21%== |
| + JEV 重排 | ✅ | 低 | 快 | ==54%== |
| [[cross-encoder]] | ❌ | — | — | — |
| LLM 重排（Gemini Flash / Flash-Lite） | ✅ | 高 | 慢 | — |

> [!warning] 关键前提
> 最终回答的准确率**高度依赖检索准确率**。上述 21% → 54% 是 Top-1 准确率；通常会有 10~20 个文本块进入 Top-K 计算，准确率会高得多。

> [!tip] 标准决定排序
> 用 `narrow` 原语提供不同排序标准（如「authoritative version two」与「fast work around」），模型给出的文档排序会**明显不同**。你提供的标准或可调控指令会显著影响重排结果——这正是传统 cross-encoder 做不到的。

## 应用场景

- RAG 流程中的**决策点**：重排、过滤、引用。
- 构建 [[GraphRAG]] 时，从语料库提取知识并验证抽取出的实体。
- 任何需要在特定节点做决策、且希望决策标准可写成策略的场景。

> [!quote] 一句话
> 你可以把 JEV 直接接入现有工作流，作为**即插即用的替代方案**，尤其适合需要在特定节点做决策的场景。
