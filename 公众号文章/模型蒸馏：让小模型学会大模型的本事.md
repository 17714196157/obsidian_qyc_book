## 概述

2015 年，Hinton 提出了蒸馏的概念。10 年过去了，这个技术已经从学术论文走进了生产环境。

> [!abstract] 一句话定义
> 模型蒸馏（Knowledge Distillation）是用大模型（**Teacher**）的输出指导小模型（**Student**）训练的过程。

### 类比理解：老师傅带徒弟

| 训练方式 | 学习方式 | 效果 |
|----------|---------|------|
| **传统训练** | 徒弟只看标准答案（ground truth），自己摸索 | 学的是"结果" |
| **蒸馏训练** | 徒弟不仅看答案，还看老师傅的解题思路（soft labels） | 学的是"思路" |

> [!tip] 老师傅的"思路"包含更多信息
> - 哪些选项是接近正确的
> - 哪些选项完全不靠谱
> - 不同答案之间的相对关系
>
> **这些信息，就是"知识"。**

### 蒸馏的数学本质

**传统训练用 hard labels：**

```
目标分布：[0, 0, 1, 0]  （猫的概率是100%）
```

**蒸馏训练用 soft labels（经过温度缩放）：**

```
Teacher 输出：[0.05, 0.10, 0.80, 0.05]
（猫80%，狗10%，兔子5%，鸟5%）
```

Student 学习这个软分布，而不是只学 hard label。

**温度参数 T 的作用：**

| T 值 | 效果 |
|------|------|
| `T=1` | 原始 logits |
| `T=3` | 更平滑的分布 |
| `T=5` | 非常平滑的分布 |

公式：`soft_logits = logits / T`

## 为什么需要蒸馏？

### 1. 降低推理成本

| 模型 | 参数量 | 推理成本 | 说明 |
|------|--------|---------|------|
| GPT-4 | 未公开 | $30/M tokens | - |
| Llama-3-70B | 70B | ¥0.15/千 tokens | - |
| Llama-3-8B | 8B | ¥0.02/千 tokens | - |
| **蒸馏版 8B** | 8B | ¥0.02/千 tokens | **质量接近 70B** |

### 2. 满足延迟要求

| 模型 | 首 Token 延迟 | 适用场景 |
|------|-------------|---------|
| 70B | 200-500ms | 离线批处理 |
| 8B | 50-100ms | 实时应用（客服、代码补全） |

### 3. 边缘部署

手机、IoT 设备跑不动 70B，但可以跑 3B-7B 的蒸馏模型。

> [!quote] 核心价值
> 蒸馏后的 8B 模型，推理成本只有 70B 的 **1/8**，但质量接近 70B。

## 蒸馏的三代演进

### 第一代：Logit Distillation（2015-2020）

> [!abstract] Hinton 的原始方法
> Student 学习 Teacher 的 soft logits。

```python
loss = alpha * CE(student_logits, hard_labels) + \
       (1-alpha) * KL(soft_student, soft_teacher)
```

| 优点 | 局限 |
|------|------|
| 简单直接 | 只传递了输出层的知识，忽略了中间层特征 |

### 第二代：Feature Distillation（2020-2024）

> [!abstract] FitNets、Attention Transfer
> Student 学习 Teacher 的中间层特征。

```python
# 对齐中间层特征
feature_loss = MSE(student_features, teacher_features)
total_loss = task_loss + lambda * feature_loss
```

| 进步 | 局限 |
|------|------|
| 传递了更丰富的表示知识 | 需要模型架构相似，难以跨架构蒸馏 |

### 第三代：Data-Free & On-Policy Distillation（2025-2026）

> [!important] 代表工作
> Be My Tutor（2026-06）、Dense Supervision（2026-06）

| 方法 | 核心 | 特点 |
|------|------|------|
| **Data-Free** | 用 GAN 生成训练数据 | 保护隐私 |
| **On-Policy** | Student 自己生成样本，Teacher 提供反馈 | 避免分布不匹配 |
| **Co-Distillation** | Teacher 和 Student 互相学习 | 共同提升 |

> [!success] 2026 年趋势
> 蒸馏不再是单向的"教与学"，而是双向的**"协作进化"**。

## LLM 蒸馏 vs 传统蒸馏

### 蒸馏目标对比

| 维度 | 传统 CV/NLP | LLM |
|------|------------|-----|
| **学习目标** | 分类分布（soft labels）<br>对齐特征表示 | 生成序列（next token prediction）<br>学习推理能力（chain-of-thought）<br>学习指令遵循（instruction following） |
| **方法** | `loss = KL(student/T, teacher/T)` | `teacher.generate(prompt)` 生成完整序列<br>`cross_entropy(student, teacher_outputs)` |

### 挑战对比

| 挑战 | 传统模型 | LLM |
|------|---------|-----|
| **数据量** | 小（ImageNet 1M） | 大（万亿 tokens） |
| **生成成本** | 低 | 高（Teacher 推理昂贵） |
| **评估** | 简单（准确率） | 复杂（多维能力） |

## 实战：用 Llama-3-70B 蒸馏 Llama-3-8B

### 环境准备

```bash
pip install transformers accelerate peft
pip install torch --index-url https://download.pytorch.org/whl/cu121

# 下载模型
huggingface-cli download meta-llama/Llama-3-70B-Instruct \
  --local-dir ./models/teacher
huggingface-cli download meta-llama/Llama-3-8B-Instruct \
  --local-dir ./models/student
```

### Step 1：生成蒸馏数据

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch
import json

# 加载 Teacher
teacher = AutoModelForCausalLM.from_pretrained(
    "./models/teacher",
    torch_dtype=torch.float16,
    device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained("./models/teacher")

# 准备 prompts
prompts = [
    "解释什么是注意力机制",
    "用Python写一个快速排序算法",
    "分析这段代码的时间复杂度...",
    # ... 更多 prompts
]

# 生成 Teacher 输出
distillation_data = []
for prompt in prompts:
    inputs = tokenizer(prompt, return_tensors="pt").to(teacher.device)
    with torch.no_grad():
        outputs = teacher.generate(
            **inputs,
            max_new_tokens=500,
            temperature=0.7,
            top_p=0.9
        )
    response = tokenizer.decode(outputs[0], skip_special_tokens=True)
    distillation_data.append({
        "prompt": prompt,
        "response": response[len(prompt):]
    })

# 保存
with open("distillation_data.json", "w") as f:
    json.dump(distillation_data, f, ensure_ascii=False, indent=2)
```

> [!warning] 踩坑记录
> 生成 10K 条数据，70B 模型需要约 **20 小时**（单卡 A100）。
>
> **建议：** 用 vLLM 加速 `pip install vllm`，速度提升 **5-10 倍**。

### Step 2：训练 Student

```python
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from trl import SFTTrainer
import json

# 加载 Student
student = AutoModelForCausalLM.from_pretrained(
    "./models/student",
    torch_dtype=torch.float16,
    device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained("./models/student")

# 加载蒸馏数据
with open("distillation_data.json") as f:
    data = json.load(f)

# 格式化数据
def format_example(example):
    return f"### Instruction:\n{example['prompt']}\n\n### Response:\n{example['response']}"

train_texts = [format_example(d) for d in data[:8000]]
eval_texts = [format_example(d) for d in data[8000:]]

# 训练配置
training_args = TrainingArguments(
    output_dir="./llama-3-8b-distilled",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-5,
    fp16=True,
    logging_steps=10,
    save_strategy="epoch",
    eval_strategy="epoch",
    save_total_limit=2
)

# 启动训练
trainer = SFTTrainer(
    model=student,
    args=training_args,
    train_dataset=train_texts,
    eval_dataset=eval_texts,
    tokenizer=tokenizer
)
trainer.train()
```

### Step 3：评估和对比

```python
from transformers import pipeline

# 加载模型
original = pipeline("text-generation", model="./models/student")
distilled = pipeline("text-generation", model="./llama-3-8b-distilled")

# 对比测试
test_prompts = [
    "解释什么是Transformer",
    "用Python实现二叉树遍历",
    "分析这段代码的问题..."
]

for prompt in test_prompts:
    print(f"\n=== Prompt: {prompt} ===")
    print("\n原始 8B:", original(prompt, max_new_tokens=200)[0]['generated_text'])
    print("\n蒸馏 8B:", distilled(prompt, max_new_tokens=200)[0]['generated_text'])
```

### 性能对比

| 指标 | 原始 8B | 蒸馏 8B | 70B Teacher |
|------|---------|---------|-------------|
| MMLU 准确率 | 65.2% | **71.8%** | 73.5% |
| 代码生成（HumanEval） | 42.1% | **58.7%** | 62.3% |
| 数学推理（GSM8K） | 38.5% | **52.1%** | 56.8% |
| 推理延迟 | 85ms | 85ms | 320ms |
| 显存占用 | 16GB | 16GB | 140GB |

> [!success] 关键发现
> 蒸馏后的 8B 模型，在多个基准上接近 70B 的性能，但**推理成本只有 1/8**。

## 高级技巧：On-Policy Distillation

| 方式 | 流程 | 问题 |
|------|------|------|
| **Off-Policy（传统）** | Teacher 生成数据 → Student 学习 | Distribution mismatch |
| **On-Policy（2026）** | Student 自己生成数据 → Teacher 提供反馈 | 学习自己生成的分布 |

### 工作流程

```
Student 生成输出
       ↓
Teacher 评分
       ↓
分数 > threshold？──是──→ reinforce(Student, Student输出)
       ↓否
correct(Student, Teacher输出)
```

### 代码实现

```python
from trl import PPOTrainer, PPOConfig

# 配置
config = PPOConfig(
    model_name="./models/student",
    learning_rate=1e-5
)

# 定义奖励函数（用 Teacher 打分）
def reward_fn(student_output):
    score = teacher.evaluate(student_output)
    return score

# On-Policy 训练
trainer = PPOTrainer(
    config=config,
    model=student,
    reward_fn=reward_fn
)
trainer.train()
```

> [!success] On-Policy 优势
> - Student 学习自己生成的分布，而不是 Teacher 的分布
> - 避免了 distribution mismatch 问题
> - 2026 年论文显示，On-Policy 比 Off-Policy 提升 **5-10%**

## 蒸馏踩坑记录

### 坑 1：温度参数选择不当

| 症状 | 原因 | 解决 |
|------|------|------|
| 蒸馏后模型性能没有提升 | 温度 T 太小，soft labels 太"硬"，信息量不够 | 尝试 T=2,3,5,7 遍历搜索 |

```python
for T in [2, 3, 5, 7]:
    soft_logits = logits / T
    # 训练并评估
```

> [!tip] 经验值
> `T=3` 到 `T=5` 通常效果最好。

### 坑 2：数据分布偏差

| 症状 | 原因 | 解决 |
|------|------|------|
| 蒸馏数据质量好，但 Student 在真实场景表现差 | Teacher 生成的数据和实际使用场景不匹配 | 1. 收集真实场景 prompts<br>2. 用真实 prompts 生成蒸馏数据<br>3. 混合 50% 真实数据 + 50% 生成数据 |

### 坑 3：过拟合 Teacher

| 症状 | 原因 | 解决 |
|------|------|------|
| Student 在蒸馏数据上表现好，但泛化能力差 | Student 过度模仿 Teacher，失去了自己的"思考方式" | 降低蒸馏权重：`alpha = 0.5`（从 0.8 降到 0.5） |

```python
alpha = 0.5
loss = alpha * distillation_loss + (1-alpha) * task_loss
```

### 坑 4：Teacher 本身有错误

| 症状 | 原因 | 解决 |
|------|------|------|
| Student 学会了 Teacher 的错误 | Teacher 在某些场景下会生成错误输出 | 1. 过滤低质量的 Teacher 输出<br>2. 人工审核蒸馏数据<br>3. 用多个 Teacher 投票 |

## 蒸馏 vs 微调 vs 量化

| 方法 | 目标 | 适用场景 | 成本 |
|------|------|---------|------|
| **蒸馏** | 提升小模型能力 | 有大模型可用，想降低成本 | 中（需要 Teacher 推理） |
| **微调** | 适应特定任务 | 需要定制行为，有标注数据 | 中（训练成本） |
| **量化** | 降低推理成本 | 模型已训练好，想加速 | 低（一次性转换） |

### 最佳实践：蒸馏 + 量化

```
70B Teacher
    ↓ 蒸馏
8B Student（质量接近70B）
    ↓ 量化（Q4_K_M）
8B Q4（约5GB，可单卡部署）
```

| 维度 | 效果 |
|------|------|
| 质量 | 接近 70B |
| 成本 | 只有 70B 的 1/10 |
| 部署 | 单卡 RTX 4090 可跑 |

## 对技术负责人的建议

### 1. 先评估是否需要蒸馏

- 70B 模型的推理成本是否过高？
- 延迟是否不满足需求？
- 是否需要在边缘设备部署？

> 如果答案是"是"，考虑蒸馏。

### 2. 选择合适的 Teacher

> [!tip] 选择原则
> - Teacher 不必是最大的模型，而是在你的场景表现最好的
> - 可以用 GPT-4 API 作为 Teacher（成本可控）
> - 多个小 Teacher 投票，效果可能优于单个大 Teacher

### 3. 数据质量是关键

> [!important] 经验
> - **1000 条高质量**蒸馏数据 > **10000 条低质量**数据
> - 蒸馏数据要覆盖真实场景
> - 人工审核前 100 条，确保质量

### 4. 持续迭代

```
部署 → 收集用户反馈 → 筛选高质量样本 → 重新蒸馏 → 更新模型
```

> 每月迭代一次，持续提升。
