## 原因分析

### 1. Guided Decoding 后端变化（概率最高）

| 版本        | 行为                                                                 | 容错率 |
| --------- | ------------------------------------------------------------------ | --- |
| **0.6.2** | `response_format: json_object` 是"后处理"模式 — 生成完整个文本后，用正则/AST 提取 JSON | 极高  |
| **0.7.x** | 引入 **outlines/xgrammar 做 token-level 约束**                          | 低   |
| **0.8.x** | 默认开启 token-level 约束引导解码                                            | 低   |

> [!important] 核心机制
> 对于 `[{...}, {...}]` 这种嵌套结构，引导解码器在以下情况会卡住：
> 1. 模型想生成一个不在 schema 允许范围内的 token（比如多了一个逗号）
> 2. 引导解码器会强制 reject 这个 token，但采样器找不到备选，导致**生成死循环或截断**
> 3. 最终返回的文本就是**半截 JSON**

**验证方法：** 在请求里加 `"guided_decoding_backend": "outlines"` 或 `"guided_decoding_backend": "xgrammar"` 分别测试，或者直接不加 `response_format` 用 `type: text` 让模型自由生成。
```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="dummy")
response = client.chat.completions.create(
    model="your-model",
    messages=[...],
    response_format={"type": "json_object"},
    extra_body={"guided_decoding_backend": "outlines"}
)
```

| vLLM 版本       | 默认 `guided_decoding_backend`     | 说明                  |
| ------------- | -------------------------------- | ------------------- |
| **0.6.x 及之前** | `outlines`                       | 后处理模式，容错率高          |
| **0.7.x**     | 引入 `xgrammar`，但默认可能仍为 `outlines` |                     |
| **0.8.x 及之后** | **`xgrammar`**                   | 默认开启 token-level 约束 |


### 2. Chunked Prefill / 调度器变化

| 版本 | 行为 |
|------|------|
| **0.7.0** | 开始默认启用 chunked prefill（大 prompt 分段处理） |
| **0.8.x** | 调度器更激进，强制开启 |

启动日志确认：
```
INFO 07-03 15:51:57 [config.py:1901] Chunked prefill is enabled with max_num_batched_tokens=2048.
```

> [!note] 问题原理
> 如果某个请求的 prefill 被 chunk 打断后，decode 阶段的 **KV cache 状态可能不一致**，导致后续生成的 token 概率偏移。

**验证方法：** 启动时加 `--disable-chunked-prefill`

## 解决方案

启动脚本调整（关键变更：`VLLM_USE_V1=0` + `--enable-chunked-prefill=False`）：

```bash
(base) ➜  medclient cat /home/maizi/vllm_server_qwen25_14b_model_qyc.sh
source activate vllm_test
CUDA_DEVICE_ORDER="PCI_BUS_ID" \
CUDA_VISIBLE_DEVICES=3 \
VLLM_USE_V1=0 \
nohup vllm serve /home/model/Qwen25-14B-Instruct \
  --served-model-name qwen2.5-14b-instruct \
  --port 8103 \
  --dtype bfloat16 \
  --api-key vllm-is-awesome \
  --max-model-len 8000 \
  --guided-decoding-backend outlines \
  --enable-chunked-prefill=False \
  --gpu-memory-utilization 0.95 \
  --uvicorn-log-level info \
  > /var/log/qwen25-14b-instruct.log 2>&1 &

```

### 关键参数说明

| 参数                               | 作用                   | 说明                                                                        |
| -------------------------------- | -------------------- | ------------------------------------------------------------------------- |
| `VLLM_USE_V1=0`                  | 禁用 V1 引擎             | V1 引擎调度策略更激进，回退到 V0 更稳定                                                   |
| `--enable-chunked-prefill=False` | 关闭分段预填充              | 避免大 prompt 被 chunk 打断导致 KV cache 不一致                                      |
| guided-decoding-backend          | 关闭token-level 约束引导解码 | 0.8.4默认打开，vLLM 0.8.x 的新约束：**引擎级别的 `guided_decoding_backend` 和请求级别的必须一致**。 |
