## 为什么用 Web Coding 做视频？

> [!question]- 为什么不用 AI 视频生成模型或 NotebookLM？
> **答案就两个字：可控。**
> - 字体、配色、每一步停留几秒、某一帧是否出现精确数字——网页里改几行代码就搞定
> - 比用视频模型"抽卡"稳定得多，成本更低
> - NotebookLM 做不了动画演示，出来的是静态图
> - Remotion 等框架反而限制了模型的发挥，不如直接让模型自由编写

**实际效果示例**：输入一篇 Anthropic 最新文章，输出一个知识讲解网页：
- 拆分为 **13 个章节**、**100+ 细粒度讲解步骤**
- 每步都有完整的视觉演示效果
- 隐藏式进度条（鼠标悬浮显示），支持任意章节跳转
- 无页眉、页码、品牌标识，画面干净像视频

## 视频制作四个关键要点

| 要点 | 说明 |
|------|------|
| **1. 口播稿改写** | 将书面化技术文章改为短句、口语化、第二人称，像跟人聊天 |
| **2. 开发计划拆解** | 每段话对应一个具体画面步骤，每几个步骤组成一个章节 |
| **3. 视觉演示设计** | 不是把文字糊上去，而是用动态效果演示抽象概念 |
| **4. 节奏同步** | 关键演示步骤必须跟随口播稿节奏，效果才自然 |

> [!warning] 核心挑战
> 模型本身不缺这些能力，但**怎么让它每次都做得出来？** 需要一套机制来驾驭过程：划定边界、设定检查点、自检和修复——这就是 **Harness 驾驭工程** 的职责。

## Harness 六组件设计拆解

Skill 本身就是一份给 Agent 看的**操作手册**，告诉 Agent 什么时候该做什么、做到什么标准、哪些红线不能碰。

![[file-20260520223835109.png]]

### 2. 工具系统

**解决问题**：模型到底能做什么。

核心就是让 Agent 把自带的**文件读写工具**用好，没有用特殊工具。

**多章节并行开发的隔离机制**：

| 隔离层      | 实现方式                      |
| -------- | ------------------------- |
| **物理隔离** | 每章独立文件夹                   |
| **命名隔离** | 每章独立 CSS 前缀，不抢类名          |
| **视觉统一** | 主题 Token 兜底，字体/颜色/间距走全局变量 |

### 3. 执行与编排

**解决问题**：让模型知道下一步该做什么。

整个流程切分为 **四个阶段**，中间卡了 **两个人工检查节点**：

| 阶段 | 内容 | 检查点 |
|------|------|--------|
| **阶段一：内容编写** | 产出**口播稿** + **开发计划** | ✅ 人工审核：稿子和计划是否满意、主题素材选择、后续开发模式 |
| **阶段二：章节开发** | 按开发计划逐章/并行开发网页 | 第一章必须人工验收，后续每章自检 |
| **阶段三：音频合成** | 调用 TTS 将口播稿合成为音频 | ✅ 人工确认是否需要自动合成 |
| **阶段四：录屏输出** | 浏览器打开网页，音频自动播放，直接录屏 | — |

### 4. 状态与记忆

**解决问题**：跨多个步骤保持连续性和稳定性。

> [!important] 核心记忆文件：`outline.md`
> - 十几章、上百步的关键决策固定下来，成为开发阶段的**持续记忆**
> - Agent 写到后面章节时，前面的决定可能已不在上下文中，文件化是兜底方案

**开发阶段 Agent 同时参考三份文档，各有分工**：

| 文档 | 职责 |
|------|------|
| **口播稿** | 整体节奏，先讲什么后讲什么，画面跟着稿子走 |
| **开发计划（outline.md）** | 每章几步、每步屏幕放什么 |
| **原始文章** | 信息密度补充，画面需要的数据案例从原文获取 |

> [!tip] 文件化的工作记忆
> 把关键状态写进文件，需要时再读回来。避免"结构对了但画面空了"或"信息很多但节奏乱了"的问题。


### 5. 约束与恢复

**解决问题**：出错了怎么办。

> [!quote] 关键原则：反馈修复的最小切片
> 先定位问题在哪一层（节奏、视觉、内容、代码），然后**只改最小的切片**，不重做整章。
> 重做整章会把已经做对的部分也改掉，用户反而更不满意。


### 6. 评估与观测

**解决问题**：系统怎么知道自己做得对不对。

> [!danger] 自评失真问题
> 让写代码的 Agent 自己评价代码写得怎么样，结果大概率是"还不错"。

**硬性自检规则**：每个关键流程完成后，必须走 **自检 → 修复 → 汇报** 流程。

| 方案 | 说明 |
|------|------|
| **最优** | Agent Teams 开独立 Reviewer Agent，从零开始逐项检查 |
| **次优** | Sub Agent 做质检 |
| **兜底** | 当前 Agent 自行逐项核查（严格逐项，不允许目测一遍就放行） |

## 工具链配置

| 工具 | 作用 |
|------|------|
| **Claude Code** | 核心执行 Agent |
| **MiniMax Token Plan** | 提供推理 + 语音合成能力（Plus 极速版，每天 9000 字语音合成额度） |
| **CC Switch** | 桌面配置工具，让 Claude Code 切换为任意自定义模型 |
| **MiniMax CLI** | 语音合成工具，Agent 直接调用无需写代码 |

> [!note]- 可选工具：Agent Teams + tmux
> - **tmux**：终端管理器，一个窗口管理多个终端会话
> - 配合 Agent Teams，每个组员出现在不同终端面板，可同时看到测试员审核和开发者编码
> - 这是 Claude 官方推荐的使用方式

### 两种多 Agent 能力对比

| 特性 | SubAgent | Agent Teams |
|------|----------|-------------|
| **工作方式** | 主 Agent 分发任务，子 Agent 独立上下文完成，结果交回 | 组长+组员，独立会话，可互相发消息、共享任务列表 |
| **适用场景** | 结果导向型任务（并行开发章节、代码检查） | 需要来回反馈的任务（质检：测试→开发→复查） |
| **Token 开销** | 较低 | 较高（每个组员都是完整会话） |
| **类比** | 派三人去三个城市办事，回来汇报 | 三人拉进同一间会议室，边讨论边改方案 |

### 环境准备
1. 安装 Claude Code，验证 `claude -v` 输出版本号
2. 配置 CC Switch → 选择 Claude → 添加 MiniMax 提供商 → 粘贴 API Key → 模型改为 MiniMax M2.7
3. 安装 MiniMax CLI：让 Claude Code 执行安装命令
4. 安装 Skill：从 GitHub 下载安装包，解压后放入 `.claude/skills/` 目录
5. （可选）启用 Agent Teams 环境变量 + 安装 tmux
### 第一阶段：内容编写

输入原始文章，Agent 自动完成：
- 编写**口播稿**（`script.md`）：决定描述方式与整体节奏（短句、快节奏、真人聊天风格）
- 编写**开发计划**（`outline.md`）：决定每章做几步、每步放什么（细粒度章节+步骤，标注每步屏幕信息）
- 编写**单章实现** （CHAPTER-CRAFT.md） ：有动图、素材真实、不套模板、代码隔离、字大留白、逐个揭示

![[file-20260520223835091.png]]
**自动创建两个 Reviewer Agent 进行质检，人工检查点确认**：
- 稿子和开发计划是否满意（可调整风格）
- 选择视觉主题（Skill 推荐或自定义风格）
- 素材准备方式（手动提供 or AI 生成）
- 开发模式选择（三种，见下表）
 **三种开发模式**

| 模式       | 说明                         |
| -------- | -------------------------- |
| **逐章确认** | 每章开发完成后人工验收，再继续下一章         |
| **顺序开发** | 第一章验收后，后续章节按顺序自动完成         |
| **并行开发** | 第一章验收后，后续章节用 SubAgent 并行开发 |

### 第二阶段：章节开发

> [!important] 第一章验收是基准
> 第一章定下来后，能看到页面密度、字体大小、动效节奏、信息呈现方式是否合理。差距大还能及时调整。

1. 第一章开发完成 → 在浏览器亲自验收
2. 确认没问题 → 启动并行开发（建议最多同时 3 个 Agent）
3. 每章完成后自动进入质检环节
4. 全部完成后整体检查：空白页、动画卡顿、步骤不对、内容错位

### 第三阶段：音频合成

- 自动从所有章节抽取口播文本清单
- 调用 MiniMax CLI 逐条合成音频
- 支持断点续传：遇到速率限制自动记录，已生成文件自动跳过
- 输出：每章子目录下，每一步对应一个音频文件

### 第四阶段：录屏输出

网页提供 **三种播放模式**：

| 模式 | URL 参数 | 说明 |
|------|----------|------|
| **手动模式** | 默认 | 不播放音频，自由切换步骤，适合自己录音 |
| **音频播放** | `?audio=1` | 每步自动播放音频，可手动切换步骤 |
| **自动播放** | `?auto=1` | 按空格键后按音频节奏自动播放 |

## 总结

> [!success] Harness 的核心价值
> 把**模型能力**、**工具能力**和**人的判断**，组织成一条**稳定可控的生产流程**。
>
> 做 Harness 不是非得从零做一个 Agent，**用一个 Skill 约束 Agent 把垂直工作做好**，也是在做 Harness。

可以用类似思路在真实工作中实践：
- 模型能力已经很强（Claude Code 能写代码、MiniMax 提供推理和语音合成）
- 关键是如何**稳定编排**这些能力
- Skill 做的事情就是把复杂内容生产任务拆成**有流程、有状态、有检查点、有自检、有恢复机制**的工程系统
