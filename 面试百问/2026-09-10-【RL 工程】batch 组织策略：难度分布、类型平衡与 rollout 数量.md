> **RL 的 batch 不是数据集，是精心配比的题库。** 随便抽 prompt 就训，模型必翻车。

---

## 1️⃣ RL Batch 与 SFT Batch 的本质区别

```
SFT Batch                    RL Batch
─────────                    ─────────
prompt → 1 个回答            prompt → 多个回答（rollout）
     ├── 正确答案                    ├── rollout 1 → reward 1
     └── 交叉熵损失                  ├── rollout 2 → reward 2
                                     ├── rollout 3 → reward 3
                                     └── ...        └── ...
                                     一个 prompt 的多个 rollout → 组成一个 Group
```

| 维度 | SFT | RL (GRPO) |
|------|-----|-----------|
| **每个 prompt 输出** | 1 个回答 | 多个 rollout（通常 4~16 个） |
| **损失计算** | 交叉熵（与正确标签比对） | 组内 z-score 归一化优势（rollout 间相对比较） |
| **信号来源** | 绝对正确信号 | **组内相对差异**——只有 rollout 间质量不同才有信号 |
| **batch 影响** | 影响不大，随机即可 | **直接影响信号质量**——需要精心配比 |

## 2️⃣ Prompt 难度分布

### 为什么难度分布这么重要？

```
全是简单题                全是难题                   理想配比
─────────────────        ─────────────────        ─────────────────
prompt 全对               prompt 全错               简单 30% ✅
↓                         ↓                        中等 50% ✅
每个 rollout 都 100 分    每个 rollout 都 0 分      困难 20% ✅
↓                         ↓                        ↓
z-score 归一化后           z-score 归一化后          有区分度
全部 = 0 ❌ 无信号        全部 = 0 ❌ 无信号         有效信号 ✅
```

> [!warning] 关键洞察
> **中等难度的题提供最多的学习信号。** 太难和太简单的 prompt，组内归一化后全部归零，梯度信号直接消失。

### 推荐配比

| 难度 | 占比 | 效果 |
|------|------|------|
| **简单** | 30% | 确保基础能力不退化，少量信号 |
| **中等** | 50% | **梯度信号最强**，核心学习来源 |
| **困难** | 20% | 推动能力边界，防止过拟合简单题 |

## 3️⃣ 难度筛选方法

### 方法一：预评估（Pre-evaluation）

```
训练前
    ↓
模型对所有候选 prompt 做推理
    ↓
按正确率分等级
    ├── 正确率 > 80% → 简单
    ├── 正确率 40~80% → 中等
    └── 正确率 < 40% → 困难
    ↓
按 3:5:2 比例采样构建 batch
```

### 方法二：动态调整（Dynamic Adjustment）

> 训练过程中模型能力持续提升——今天的中等题，下周可能变成了简单题。

- **持续评估**：每隔 N 步重新评估 prompt 难度等级
- **动态切换**：模型进步后，把"变简单"的 prompt 降级，补充新的中等/困难题

### 方法三：GRPO 天然自带筛选机制

GRPO 的 group 内做 **z-score 归一化**——

```
Â_i = (r_i - mean) / std
```

只有 group 内**有多种质量**的 rollout 时，z-score 才不为 0。如果 group 内所有 rollout 的 reward 完全一样，Â_i 全部 = 0 → **没有有效信号**。

> 所以即使你不做显式的难度筛选，GRPO 也会自动忽略"全对"和"全错"的 group。但显式配比能大幅提高信号效率。

## 4️⃣ Prompt 类型平衡

### 问题

数学、代码、推理、常识等多种类型——如果某一类 prompt 主导 batch，模型会**偏科退化**：

```
Batch 里 80% 是数学题
    ↓
模型疯狂优化数学能力
    ↓
代码能力倒退
    ↓
整体评估分数反而下降
```

### 解法

| 策略 | 做法 |
|------|------|
| **均匀采样** | 按任务类型均匀采样，确保每类 prompt 数大致相同 |
| **目标能力配比** | 维护多个 prompt 池（数学池、代码池、推理池……），每次按**预设比例**从各池采样 |

```
    数学池 ──┐
    代码池 ──┤
    推理池 ──┼──→ 按比例混合采样 → 一个 Batch
    常识池 ──┤
    其他池 ──┘
```

---

## 5️⃣ Rollout 数量

### 数量权衡

| Rollout 数量 | 问题 |
|:------------:|------|
| **太少（< 4）** | z-score 不稳定，少数 outlier 主导归一化结果 |
| **太多（> 16）** | 计算开销高，**收益递减**——额外 rollout 带来的信息增益越来越小 |
| **GRPO 论文** | 使用 **8~16 个** |
| **经验推荐** | **4~16 个**是甜区 |

### 自适应 Rollout 分配

```
简单题 ─→ 少采几个（如 4 个）
             ↓  rollout 结果差不多，不需要很多样本区分
中等题 ─→ 标准数量（如 8 个）
             ↓
困难题 ─→ 多采几个（如 16 个）
             ↓  需要更多样本来覆盖解空间
```

> 简单题少采，难题多采——在保证信号质量的同时**节省计算资源**。

## ✅ 总结

> [!quote] 一句话带走
> **RL 的 batch 不是数据集，是精心配比的题库。**

| # | 要点 | 推荐值 |
|---|------|--------|
| 1 | 难度分布——中等题信号最强 | 简单 30% : 中等 50% : 困难 20% |
| 2 | 难度筛选 | 预评估 / 动态调整 / GRPO 自带 z-score |
| 3 | 类型平衡——防止模型偏科 | 多个 prompt 池，按比例混合采样 |
| 4 | Rollout 数量 | 4~16 个，自适应分配 |
| 5 | 监控 reward 方差 | 方差塌了的 batch 直接丢掉 |
